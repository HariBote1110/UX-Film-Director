# 総評
**リリース禁止。** 履歴スタックを invasively 直書きする割に「undo/redo の非同期性」「future スタック無効化」「記録静默諦め」の三つの不変条件を一切守っていない。undo が効かなくなる、または効きすぎて壊れる経路が複数ある。

## 所見 1: 未解決（pending）undo/redo 中の記録・合体がスタックを破壊する
**ファイル:行**: useStore.ts:692-731（特に 702-705, 714, 718）
**再現手順**:
1. スライダーをドラッグ → updateObject が C を記録
2. Cmd+Z を押下（非同期 pending。past 末尾はまだ C のまま）
3. ドラッグ継続中の updateObject が到達 → top===C が成立し、(a) C を C'(undo 要求より後の編集を含む) に差し替え、または (b) 新コマンド D を push
4. undo が解決し末尾を pop → 撤回されるのはユーザーが undo しようとしたコマンドではなく C' や D。redo 側でも同様に、新編集の上に旧 previous/next のコマンドが再生される

**根拠**： 前提から編集は pending 中も可能なのに、canCoalesce・push・merge はいずれも isCommandHistoryPending を参照していない。
**深刻度： 高**

## 所見 2: 合体・正味ゼロ除去・カメラ amend が生の setState で過去の履歴を書き換え、redo スタックを無効化しない
**ファイル:行**: useStore.ts:714, 718, 1540, 1544, 1573
**再現手順**:
1. 編集 A → Cmd+Z（redo スタックに F が退避）
2. 1 秒以内に同一オブジェクトへ別操作 → canCoalesce 成立 → 714 の set() は末尾差し替えのみ実施。pushHistoryCommand を経由しないため、F の破棄が行われない
3. redo 実行 → F が「新しい編集適用後」の状態に旧時点の値で再生され、状態が分岐

**根拠**: pushHistoryCommand が担うはずの future 破棄・履歴簿記の類は、合体パス、カメラの merge/amend/正味ゼロ除去、すべて別系統ですね。引数を無視して全部回避されている。
**深刻度: 高**

## 所見 3: 代表不可能なフィールドを 1 つ含むだけで、そのオブジェクト更新全体の undo 可能性が静かに消失する
**ファイル:行**: useStore.ts:695-697
**再現手順**:
1. UI が一時プロパティ（選択ハイライト、キャッシュ等）付きで updateObject(id, { x: 10, someRuntimeField }) を呼ぶ
2. 状態は適用されるが isFieldDiffRepresentable=false → x の変更ごと履歴から消える
3. Cmd+Z → ユーザーの目線では「x の変更が取り消されず、無関係な直前操作が巻き戻る」

**根拠**: バッチ内 697 も同様で、複数オブジェクト中 1 つでも該当するとそのオブジェクトだけ欠けた「部分的に undo できないバッチ」が完成する。失敗の通知もフォールバック（フィールド単位の選択的記録）も無い。
**深刻度： 高**

## 所見 4: lastRecordedObjectUpdate / lastStageCameraCommand の陳腐化により、undo 境界・シーン境界を跨いだ誤合体が発生する
**ファイル:行**: useStore.ts:700-705, 1531-1533（リセットなしは注記記載の通り）
**再現手順**:
1. objX を編集し C を記録（lastRecorded={X,C}）→ カメラ操作を記録 → undo でカメラが退避、past 末尾がふたたび C になる（bridge 往復込みで 1 秒以内に到達可能）
2. objX を別の操作 → top===C・objectId 同一・窓内がすべて成立し、undo を跨いで C に合体する。新規編集が「undo 後の新ステップ」にならず、個別 undo が不可能になる
3. カメラ側も同様に、undo → redo で同一コマンド参照が再び末尾に戻った直後に合体する。lastStageCameraCommand は undo でもリセットされない
4. シーン切替でもリセットされないため、履歴がシーンを跨いで共有される構成では、別シーンの異なるオブジェクトが ID 衝突で直前コマンドに合体し得る

**深刻度: 中**

## 所見 5: amend の誤爆保護が「null を返すだけ」で、カメラドラッグの残尾が無記録のまま取り残される
**ファイル:行**: useStore.ts:1567-1568
**再現手順**:
1. カメラドラッグ中（record 済み、amend ループ中）にオブジェクト削除等で履歴 push
2. top!==command で null を返却するが、ドラッグ終了位置を誰も記録しない
3. 状態は終端位置、コマンドの next は途中位置 → undo→redo で最終カメラ位置と異なる状態に発散する

**根拠**: amend 失敗の代替手段（新規 record への委譲）も呼び出し側への通知も無い。undo 回復後の状態が、undo 前の状態と一致しなくなる。
**深刻度： 中**

## 所見 6: バッチ flush が例外時には履歴を静かに消失する
**ファイル:行**: useStore.ts:1586-1590
**再現手順**:
1. withObjectHistoryBatch 内で複数オブジェクトの更新を収集
2. buildBatchCommand 成功後 1588 で収集配列を先に空にしてから 1590 で push する
3. pushHistoryCommand 内のいずれかで例外が発生した場合 → 差分は状態に反映済みにもかかわらず、履歴には存在せず、undo の機会が失われる。収集配列も空のためリカバリ不能なまま、二次例外で元の例外も置換される

**根拠**: fn() 途中で throw した場合でも finally が未完成の部分差分をそのまま flush しており、呼び出し側が失敗時にロールバックを試みた場合に補償が履歴に二重に積まれる余地もある。
**深刻度： 中**
