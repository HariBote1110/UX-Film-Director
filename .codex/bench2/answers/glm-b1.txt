**欠けている処理：イージング適用後の値（`eased`）の `[0, 1]` への clamp。**

キーフレーム分岐では `clamp(easing(progress), 0, 1)` を挟んでおり、Rust 側も `.clamp(0.0, 1.0)` しているのに、animation 分岐は `easing(progress)` の結果をそのまま補間に使っている。

**発生条件：**
- `enableAnimation === true` かつ `duration > EPSILON`
- `easing` に `easeOutBack` / `easeInBack`（カーブが途中で 1 を超える / 0 未満になるもの）
- `time` がアニメーション途中（`0 < progress < 1`、特にカーブが範囲外に出る区間）

**不具合の内容：**
- **easeOutBack**：`eased > 1` の区間で、位置が終点 `(endX, endY)` をさらに通り越して「行き過ぎる」。目標位置を飛び越えてから戻る、意図しないオーバーシュートになる。
- **easeInBack**：`eased < 0` の区間で、位置が始点 `(x, y)` より逆側に外れ、出発点の後ろへはみ出してから進み始める。
- **他実装との不一致**：Rust は clamp しているため、同じ条件でも位置が TS と一致しない。プレビューとレンダリング（または他実装の基準値）でフレームごとの座標がズレ、位置ズレ・揺れの差異として現れる。キーフレーム有りのオブジェクトは TS 側も clamp しているため、キーフレーム無しの animation オブジェクトだけ挙動が変わる点も一貫性を欠く。
