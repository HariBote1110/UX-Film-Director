**最終的な不透明度倍率（fade が 2 つ、opacity 0.5 × 2）**

- **TS: 0.25** — アキュムレータに乗算して積算するため `1 × 0.5 × 0.5 = 0.25`
- **Rust: 0.5** — `fade = clamp(...)` は代入なので «後勝ち» で上書きされ、走査順で最後の fade の値 `0.5` だけが残る

**差異が生じる条件**

- fade が **0 個または 1 個**なら両者は一致（クランプ済み opacity そのもの）。
- **2 個以上**ある場合、TS は全 fade の積、Rust は最後の 1 つの値を採るため、基本的に異なる。一致するのは例外ケースのみ：
  - 最後の fade の opacity が 0（両方 0 になる）
  - 最後より前の fade がすべて opacity 1.0（積が最後の値と等しい）
- つまり「**最後より前に opacity < 1 の有効な fade があり、かつ最後の fade の opacity が 0 でない**」ときに差が顕在化する。

**片方だけに現れる振る舞い**

- **TS のみ**：複数 fade が乗算的に重なる（結果は各値の最小値以下になり、重ねるほど薄くなる）。乗算は可換なので**フィルタ順序に依存しない**。どこか 1 つでも opacity 0 があれば全体が 0。
- **Rust のみ**：**last-write-wins（後勝ち）**で、走査順の最後の fade 以外は完全に捨てられる。結果が**順序で変わる**（例: [0.5, 1.0] → 1.0、[1.0, 0.5] → 0.5）。前の方の fade の 0 も後続の fade で上書きされ無効化される。
- 補足：TS は `filter.enabled` を確認して無効な fade をスキップするが、Rust の抜粋にはその判定が見当たらない。他箇所でチェックしていなければ、**無効な fade も後勝ちの上書きに参加してしまう**点に注意が必要。
