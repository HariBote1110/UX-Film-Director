# AviUtl 互換ギャップ分析（2026-02-11）

## 前提
- 比較対象は公式配布 `aviutl110.zip`（`AviUtl version 1.10`）および `exedit92.zip`（拡張編集）。
- 本ドキュメントは現行実装（`src/`, `electron/`, `rust-backend/`）を基準に、AviUtl 相当機能への不足を整理する。

## 現行実装サマリ（確認済み）
- タイムライン編集: オブジェクト追加、移動、長さ変更、分割、削除、Undo/Redo。
- 対応オブジェクト: `text`, `shape`, `image`, `video`, `audio`, `psd`, `group_control`, `audio_visualization`。
- 主要効果: 色調補正、クリッピング、斜めクリッピング、振動、影、グラデーション。
- 書き出し: Rust バックエンド経由の MP4 出力（フレーム書き込み）。

## ギャップ一覧

### A. 編集基盤
- 未実装: プロジェクト保存/読込（`.aup` 相当の永続化）。
- 未実装: シーン（複数タイムライン切替）。
- 不足: レイヤー運用（AviUtl は 100 レイヤー。現状 20 固定、ロック/表示/名称変更/挿入削除なし）。
- 不足: 複数選択、コピー/貼り付け、切り取り、複製、グループ化/解除。
- 不足: 中間点（キーフレーム）の UI 編集。

### B. オブジェクト/エフェクト
- 未実装: カメラ制御、カメラ効果、拡張描画（3D 回転/Z 軸運用）。
- 未実装: フィルタ効果スタック（追加/削除/順序変更/ON-OFF）。
- 大幅不足: 拡張編集の主要フィルタ群（キー系、ブラー系、マスク、ワイプ、極座標、ディスプレイスメント、時間制御など）。
- 未実装: スクリプト制御/カスタムオブジェクト互換レイヤ。

### C. 入出力/運用
- 不足: AVI/WAV/プラグイン出力、バッチ出力。
- 不足: エクスポート音声合成パスが未接続（`audioPath` 引数はあるが呼び出し側で未使用）。
- 未実装: オブジェクトファイル入出力（`.exo`, `.exa` 相当）。
- 不足: キー操作カスタマイズ、グリッド(BPM/XY/カメラ)、詳細スナップ設定。

## 実装優先順位（AviUtl カバレッジ最大化向け）

### P0（最優先: 先に無いと全体設計が崩れる）
1. プロジェクト保存/読込基盤（JSON スキーマ + 後方互換方針）。
2. レイヤー基盤拡張（100 レイヤー、表示/ロック/名称、挿入削除）。
3. 複数選択 + コピー/貼り付け + 複製 + グループ化解除。
4. フィルタスタック基盤（任意個のエフェクト配列、順序管理、ON/OFF）。
5. エクスポート音声統合（タイムライン音声レンダリングを `start-export.audioPath` へ接続）。

### P1（高優先: AviUtl らしさの中核）
1. 中間点（キーフレーム）編集 UI と補間種別の明示管理。
2. シーン機能（最低: ルート + サブシーン呼び出し）。
3. カメラ制御 + 拡張描画（2.5D から開始）。
4. 主要フィルタ第1群: ぼかし、境界ぼかし、モザイク、フェード、ワイプ、マスク、方向/放射ブラー。

### P2（中優先: 実運用互換）
1. 主要フィルタ第2群: クロマキー/カラーキー/ルミナンスキー、ミラー、極座標、波紋、ノイズ、色ずれ。
2. オブジェクトファイル入出力（`.exo` 互換は段階対応）。
3. グリッド/BPM/スナップ詳細設定。
4. バッチ出力（複数ジョブ管理 + 再実行）。

### P3（拡張優先: 上級互換）
1. スクリプト制御層（Lua 互換そのものではなく、互換 API 層を設計）。
2. エイリアス/プリセット運用（`.exa` 相当）。
3. プラグイン拡張モデル（安全なサンドボックス前提）。

## 推奨実装順（短期ロードマップ）
1. `P0-1` プロジェクト永続化
2. `P0-2` レイヤー基盤拡張
3. `P0-3` 複数選択とクリップボード操作
4. `P0-4` フィルタスタック基盤
5. `P0-5` 音声統合エクスポート
6. `P1`（中間点 → シーン → カメラ → フィルタ第1群）

## 備考
- まず「基盤互換（P0）」を完了しないと、後続のフィルタ・カメラ実装で仕様の再設計が発生しやすい。
- AviUtl の「全カバー」を目指す場合、`P0 + P1` 完了時点で体感互換性は大きく向上する見込み。
