## 1. アニメ撮影機能

### 1.1 「撮影」とは

日本の商業アニメ制作における「撮影」は、作画・背景・3D素材を1つの画面に合成し、光や空気感を加えて最終画面を作る工程（コンポジット）。業界のデファクトツールは After Effects。本機能は「AEで撮影さんが日常的に行う処理」を UX Film Director のフィルタ/カメラ機能として提供することを目指す。

参考: [Wikipedia: 撮影 (アニメ制作)](https://ja.wikipedia.org/wiki/%E6%92%AE%E5%BD%B1_(%E3%82%A2%E3%83%8B%E3%83%A1%E5%88%B6%E4%BD%9C))、[Adobe: 『きみの色』撮影監督インタビュー](https://blog.adobe.com/jp/publish/2024/08/23/cc-video-aftereffects-interview-kiminoiro)、[アニメーション撮影の基本処理](https://note.com/senzui/n/n0d16db89be1c)、[アニメ撮影の基本: 合成モード](https://note.com/taka2composite/n/n040c7d42053d)、[エモく見えるエフェクトのかけ方](https://note.com/tomoex/n/n325babc1bcba)

### 1.2 一般的に広く使われる撮影処理カタログ

光・空気感（撮影処理の中核）:

- **ディフュージョン**: 画面全体に光の拡散を薄くかけ、素材同士を馴染ませて「アニメらしい」画面にする。最も使用頻度が高い基本処理。
- **グロー**: 光源・ハイライト部分の輝きを拡散させる（窓からの差し込み光、金属光沢、夜景、魔法エフェクト等）。閾値＋ぼかし＋加算合成。
- **パラ（パラフィン）**: 画面の一部にグラデーション状の明暗を乗せ、光の方向や時間帯を演出する（上からの光パラ、下暗パラ等）。
- **透過光（T光）**: 強い光源のフレア表現。セル時代からの伝統技法のデジタル再現。
- **フレア/ビネット**: レンズフレアと周辺減光。画面の情報量と視線誘導を作る。

線・色:

- **色トレス**: 主線（輪郭線）の色を黒から周辺色に変える処理。
- **スムージング**: 線のジャギー平滑化。素材取り込み時の基本処理。
- **色収差（RGBずれ）**: 現行実装に既にあり（AviUtl Pack由来）。撮影文脈でも常用。
- **グレイン/ノイズ**: フィルム粒状感の付与。

カメラ・光学:

- **被写界深度（ラックフォーカス）**: レイヤーのZ位置または指定値に応じたぼかしで前後ボケを作り、ピント送りを演出する。
- **カメラワーク**: PAN（横移動）、T.U./T.B.（寄り/引き）、Follow。2Dではフレーム自体の移動・拡縮として実装できる。
- **画面動（カメラシェイク）**: 揺れ・衝撃の演出。既存の「振動」フィルタの拡張で対応可能。
- **背景スライド/マルチプレーン**: レイヤーごとに異なる速度でスライドさせ奥行きを出す。既存3Dステージ（Z位置＋透視カメラ）と統合すると自然に実現できる。

合成基盤:

- **合成モード（ブレンドモード）**: 加算・スクリーン・乗算・オーバーレイ。グロー/パラ/透過光はすべて合成モードの上に成り立つため、これが最優先の基盤。
- **マスク/ワイプ**: 部分適用のための基盤。AviUtlギャップ分析でも未実装として記録済み。

### 1.3 優先順位（案）

| 優先度 | 項目 | 理由 |
|---|---|---|
| P0 | 合成モード（加算/スクリーン/乗算） | 撮影処理ほぼ全ての前提基盤 |
| P0 | ガウスぼかし単体フィルタ | ディフュージョン/グロー/DoFの構成部品 |
| P1 | ディフュージョン、グロー | 使用頻度最大。「アニメっぽさ」の即効性が高い |
| P1 | パラ（グラデーション乗算/スクリーン） | 既存グラデーション描画の応用で実装コストが低い |
| P2 | 被写界深度、カメラワーク | 既存3Dステージ・カメラと統合して実装 |
| P2 | 色トレス、グレイン、ビネット | 単体フィルタとして独立に追加可能 |
| P3 | 透過光、レンズフレア、マルチプレーン統合 | 表現力は高いが個別実装コストが大きい |

### 1.4 既存実装との接続

- フィルタスタック基盤（追加/削除/順序/ON-OFF）は実装済み。ただし「複数フィルタ同時合成」が未完（`AviUtl_Gap_Analysis.md` B項）であり、撮影処理は多段合成が前提のため、まずここを完了させる必要がある。
- 描画はRust/WebGPU側（shared-renderer / native-overlay）へ移行中のため、新規フィルタはWebGPUシェーダとして設計し、preview/exportの画素一致テスト（golden-harness）を通すことを完了条件とする。

## 2. 3D空間オーディオ

### 2.1 現状

- 3Dステージは実装済み: `editorMode: '2d' | '3d'`、透視カメラ `StageCamera3D { position, target }`（`src/types.ts`）、PSDのワールド配置 `PsdWorldPlacement`（position/rotationY/scale/billboard、`src/utils/stage3dMath.ts`）。
- 音声は `src/utils/audioMixdown.ts` が OfflineAudioContext で2chステレオへミックスするのみ。パン・距離減衰・向きの概念はない（volume/mutedのみ）。

### 2.2 構想: ステージ上の位置から音が定位する

3Dステージに置かれたオブジェクト（立ち絵PSD＋紐づく音声、または音声オブジェクト自体のワールド配置）とカメラの位置関係から、音の定位・距離感を自動で再現する。

- **リスナー = カメラ**: `StageCamera3D.position` と `target`（視線方向）を Web Audio の `AudioListener` に写像する。
- **音源 = オブジェクトのワールド位置**: `PsdWorldPlacement.position` と同形式の `Vec3` を音声オブジェクトに持たせる（`worldAudio: { enabled, position, ... }` のようなオプトイン形式で後方互換を守る）。
- **定位エンジン**: Web Audio `PannerNode` を使用。
  - `panningModel: 'HRTF'`（ヘッドホン向けの本格定位）と `'equalpower'`（軽量・スピーカー向け）を選択可能に。
  - `distanceModel`（inverse/linear）、`refDistance`、`maxDistance`、`rolloffFactor` で距離減衰を制御。
  - 必要なら `coneInner/OuterAngle` で指向性（キャラが後ろを向くとこもる等）。
- **preview/export一致**: 再生時は `AudioContext`、書き出し時は既存の `OfflineAudioContext` ミックスダウンに同じ PannerNode グラフを組み込む。OfflineAudioContext でも PannerNode/HRTF は動作するため、既存の `buildExportAudioMixWav` / `buildExportAudioBuffer` のGainノード直結部分をパンナーグラフ経由に拡張する形になる。
- **キーフレーム対応**: 位置がキーフレームで動く場合、`setValueAtTime`/`linearRampToValueAtTime` でパンナーのpositionを時間軸に沿って駆動する。

### 2.3 段階案

1. **Phase A（ステレオパン）**: カメラ相対の左右角度→equalpowerパン＋距離減衰のみ。UIはワールド配置の流用で、まず「位置と音が連動する」体験を作る。
2. **Phase B（HRTF）**: PannerNode HRTF切替、export経路への組み込み、preview/export一致テスト。
3. **Phase C（演出拡張）**: 指向性コーン、簡易リバーブ（部屋の広さ）、ドップラー（必要なら）。

### 2.4 制約・懸念

- HRTFはヘッドホン前提の表現。スピーカー再生向けにequalpowerとの切替UIが必要。
- 書き出しは現状2ch固定。5.1ch等のマルチチャンネル出力は本構想のスコープ外とする。
- 撮影機能のカメラワーク（1.2）と同じカメラ状態を参照することで、「画とカメラと音が一体で動く」ことが本機能の差別化点になる。
