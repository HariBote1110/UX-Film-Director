## 5 指標への対応状況

1. **体感インポート時間**: パース区間は 5.9 倍速。end-to-end（テクスチャ到達まで）は
   macOS 実機での実験 3 が未実施のため未確定。
2. **メインスレッド阻害**: 未計測（macOS 実機マター）。Rust 完結は構造的に有利。
3. **メモリピーク**: 可視限定で -52%。**採用**。
4. **スケーラビリティ**: 並列は N=8 頭打ち（帯域律速）だが可視限定と併用で両立。
   より大きい PSD・レイヤー数での外挿は未検証。
5. **段階的表示**: メタデータ 0.07ms の実測により実現可能性は確定。実装は未着手。

## 確定した設計知見（本実装移植時の仕様）

- 並列度は 8 で打ち切る（12 への増加は無利得）。
- インポート時は可視レイヤーのみデコード、非可視はトグル時オンデマンド
  （平均 0.32〜0.52ms/layer。ただし大レイヤーの裾は未計測で UX リスク要確認）。
- 搬送は native overlay の in-process パターン（RgbaFrame 直結）を per-layer に一般化。
  Electron 経由の disk-blob 方式（media.rs 現行 psd.parse）は再利用しない（棄却済み）。
- メタデータ（ツリー JSON）は先行返却し、stable_id は Rust 発行に一元化する。

## 棄却記録（再調査禁止）

- スレッド数スケーリング仮説（≦60ms @ 8-12T）: 棄却。帯域律速。
- 時間のバイト線形モデル: 棄却。レイヤーあたり固定コストが小レイヤーで支配的。
- WASM 経路の復活: 実験 1 と PSD_WASM_Challenge.md の両方で二重に棄却済み。

## 実験 3（end-to-end、macOS 実機）の最終結果 — 2026-08-08〜09 追記

二重デコード発見（double-decode-discovery.md）により per-layer テクスチャ導線は不要と判明。
path B = ag-psd スキップ＋Rust 真メタデータのみパース（`parse_psd_meta_only`）で決着。

| 経路 | input→parsed | end-to-end（2回目安定） |
|---|---|---|
| path A（現行 ag-psd Worker） | 638ms | 680ms |
| path B v1（parseMeta、全量デコード残存） | 323ms | 352ms |
| **path B′（真のメタデータのみ）** | **17.7ms** | **56.4ms（12.1倍速）** |

- 指標 1（体感インポート時間）: **勝利確定**（12 倍速）。
- 指標 5（段階的表示）: 実質達成——ツリーは 17ms で出る。表示合成は既存 Rust 経路が担う。
- コード: `psd.parseMeta` RPC + `psdRustImport=1` フラグゲート（版 490b、e2e 3 ブート×2 回で検証済み）。

## 本実装昇格前の残チェックリスト

- ag-psd 由来メタデータの同等性未検証分: 16bit depth、ラジオグループ初期可視、
  レイヤー名エンコーディングのエッジケース。
- 大型 PSD（100MB 級・数百レイヤー）でのスケール検証（指標 4 の外挿）。
- 非可視レイヤーのサイズ分布と最悪トグル遅延の計測（可視限定デコードを本実装に入れる場合）。
- T5（native present 信号）が未配線のため、体感の最終確認は目視または T5 配線後。
- フラグ既定 ON 化と ag-psd 経路の撤去判断（フォールバックとして残すか）。
