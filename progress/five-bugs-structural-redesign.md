# 5バグの根本原因と構造的解決の設計方針

## 決定

対処療法を採らず、以下の不変条件をアーキテクチャとして確立する。

> キャンバスに描かれるすべての視覚要素（本体・選択装飾を含む）は、単一のバージョン付きシーン状態から導出され、1フレームには単一バージョンの状態だけが合成される。

着手順序と内容:

1. **診断の状態/イベント分離**（赤テキスト対策）
   - presenter の健全性を「状態」（ready / degraded / failed + reason）と「イベント」（一過性のフレームスキップ等）に分離。
   - 分類は書き込み元（`sharedRendererPreviewPresenterController.ts`）で一度だけ行う。transient はデータセットの永続状態に書かず、カウンタとしてのみ記録。
   - UI バナーは degraded / failed の持続状態のみ表示。`Viewport.tsx` の表示側ホワイトリスト（`isNonBlockingSharedRendererPreviewDiagnostic`）は撤去。
2. **可視性述語の統一 + 選択装飾のシーングラフ化**（幽霊選択枠・選択枠ズレの前半）
   - 時間的可視性判定を単一モジュールに統合し、ヒットテスト・スナップショット・オーバーレイ全てが参照。
   - 選択装飾クアッドを Rust シーンスナップショットに含め、本体と同一フレームで合成（stateVersion 付与）。SVG オーバーレイはヒットリージョン専用化。
3. **リテインドシーングラフ + パッチ更新**（選択枠ズレの後半）
   - Rust 側がシーングラフを常駐保持し、ドラッグ中は差分パッチのみ送信。present はレンダラ側 vsync 駆動。presenter 再起動の概念を廃止。
4. **デコーダ書き換え**（ガタつき対策）
   - ffmpeg CLI サブプロセス + stdout パイプ + CPU RGBA 変換を廃止。
   - VideoToolbox インプロセスデコード、NV12/IOSurface のまま wgpu へゼロコピーインポート、YUV→RGB はシェーダで実行。
   - 専用デコードスレッド + pts 順の先読みリングバッファ（push 型）。デマルチプレクサ常駐・キーフレームインデックスのキャッシュでコールドリスタート廃止。
5. **フォント選択 UI**
   - フォント一覧の供給源は描画側の cosmic-text `FontSystem`（rust-backend に `fonts.list` RPC 追加）。UI は PropertyPanel に検索可能なコンボボックス。

## 検討して却下した代替案

- **選択枠をドラッグ中だけ隠す / 本体フレームに枠更新をスロットルで合わせる** — レイテンシ差は縮むが2導出経路の構造は残り、混在セッション等で再発する。
- **診断バナーの理由文字列ホワイトリスト追加**（`videoTextureViewUnavailable` を非表示リストへ）— 新しい transient 理由が増えるたびに再発する構造のため却下。
- **デコーダのバッファ増量・CRC32 削除等の緩和** — フレームあたり 12〜96ms の CPU 変換コスト（実測: markdown/Rust_Preview_Jank_Handoff.md）の根が残るため却下。

## 制約・注意点

- 動画+図形の混在セッションは presenter 再利用パス対象外でフル再起動（約28ms/回）になる既知の穴がある（Viewport.tsx:185-201 のコメント参照）。フェーズ3で概念ごと解消する。
- `getObjectWorldCorners`（sceneHitTest.ts）には時間可視性チェックが無い。native-overlay/src/lib.rs も受信済み装飾を無条件に毎フレーム描画する。装飾の生存期間はシーングラフに紐付けること。
- ffmpeg は Homebrew 依存で `scale_vt` 対応が環境依存。フェーズ4完了までは CPU フォールバックが残る。
- テキスト測定はフロント側 Canvas2D（ブラウザのフォント解決）で行われ cosmic-text と乖離しうる。将来的に測定も Rust へ寄せる余地あり（フェーズ5では対象外）。
