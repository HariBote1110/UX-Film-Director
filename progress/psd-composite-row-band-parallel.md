# PSD合成の行バンド並列化 — 表示高速化3部作の最終弾

## Decision

- `composite_visible_psd_layers_with_filter`（3つの公開合成入口が全て通る唯一の内部関数）を
  継ぎ目として、行バンド並列合成へ切替（版 491c、`36205b09`）。公開API・3呼び出し経路は無変更。
- `rayon::par_chunks_mut` でキャンバスをスレッド数分の行バンドに分割し、各バンドが
  担当行の範囲でレイヤーを順序どおり source-over。プールは stage 1 の共有プール
  （`OnceLock`、`min(8, cores)`）を再利用。
- 選択ロジックは `collect_composite_layers` に抽出し、本番並列経路とテスト専用
  シリアルオラクル（`#[cfg(test)]`）が同じ選択を共有。オラクルは本番から呼ばれないため
  第二の本番経路化しない。
- 研究実測（vm_tuning_research/notes/composite-parallelisation.md）: N=8 で
  葵116→19ms / 茜ver0.7 374→92ms / 或窓40→15ms、12構成バイト一致。

## Alternatives considered

- レイヤー並列 → 棄却（source-over はピクセル毎にレイヤー順序依存。順序を保てるのは
  キャンバス領域分割のみ）。
- 垂直クリップ同様に水平クリップも事前計算 → 見送り（左右のはみ出しは行バンドと独立。
  per-pixel 境界チェックを維持）。

## Constraints / Gotchas

- 垂直クリップを (layer, band) 毎の行範囲交差へ前倒しできるのは、`par_chunks_mut` が
  キャンバスを余りなく正確に分割しバンド行が常に `[0, canvas_height)` 内である構造前提。
- 幅0・空選択はプールに入る前に短絡（zero-length chunk での panic 回避）。
- 1px高キャンバス（バンド数>行数）はテストで固定。オラクル一致テスト4本が回帰ゲート。
